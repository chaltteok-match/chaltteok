# 평가 요구사항

주최측이 공지와 질의응답으로 밝힌 내용이다. 추측은 적지 않는다.
「예정」은 변경 가능성이 있다고 주최측이 밝힌 것, 「미정」은 아직 답이 없는 것이다.

마지막 확인: 2026-09-03

## 1. 제출

| 항목 | 내용 |
| --- | --- |
| 마감 | 2026-09-06(일) 23:59 KST |
| 방법 | 구글폼으로 Endpoint URL 제출 |
| 제출물 | Endpoint URL, 전처리 산출물, 재현 가능한 환경 구성 정보, 기술제안서 |

- 전처리 산출물도 제출 대상이다. 대용량이면 클라우드 스토리지 링크로 대체할 수 있다.
- Dockerfile은 필수가 아니다. 단 `requirements.txt` 등 재현 가능한 환경 구성 정보는 제출해야 한다.
- 기술제안서에 분량·양식 제한은 없다.
- 대회에서 제공한 저장소가 따로 있다. 작업은 우리 저장소에서 하고 완료 후 옮긴다.

## 2. 평가 호출

| 항목 | 값 | 상태 |
| --- | --- | --- |
| 호출 방식 | sequential. 질의가 한 건씩 순서대로 들어온다 | 확정 |
| 응답 타임아웃 | 300초 | 예정 |
| 재시도 | 호출 에러 시 2회 | 예정 |
| HTTPS 필수 여부 | — | 미정 |
| 평가 서버 가동 시간대 | — | 미정 |

- 응답 스키마의 각 항목(`think_trace`, `retrieved_context`, `answer` 등)은 **string 타입**이어야 한다.
- 빈 문자열 반환은 문제되지 않는다. `think_trace`의 형식 규정은 없다.
- 제공 코퍼스로 답할 수 없는 질의가 섞여 들어온다. 「정보한계대응」이 평가 항목이다.

## 3. 서버 운영

- 장애 등의 이유로 서버를 다시 띄우는 것은 실격 사유가 아니다. 제출 결과물을 바꿀 목적이 아닐 때에 한한다.
- 대회 Organization의 GitHub Actions는 비활성화되었다. push·pull·clone·PR은 그대로 쓸 수 있고, Actions 사용 여부는 평가에 영향이 없다. CI가 필요하면 로컬이나 네이버클라우드에서 돌린다.
- 저장소 deploy key 등록은 조직 정책으로 막혀 있다. 대신 fine-grained PAT을 쓴다.

### fine-grained PAT

서버가 저장소 코드를 내려받으려면 인증 수단이 필요하다. 계정 비밀번호 대신 쓰는, 범위를 좁힌 열쇠다.

발급 경로는 GitHub `Settings → Developer settings → Fine-grained tokens`이다.

| 항목 | 지정할 값 |
| --- | --- |
| Resource owner | 대회 organization |
| Repository | 본인 팀 저장소 |
| Permissions | Contents: Read-only |

`Read-only`이므로 이 토큰으로는 코드를 읽기만 하고 밀어 넣을 수 없다. 서버가 털려도 저장소가 훼손되지 않는다.

생성하면 organization 관리자 승인 요청이 접수된다. 승인 전에는 `waiting admin approval` 상태이고 쓸 수 없다.

## 4. 비용

- 제공 크레딧은 부가세를 포함하며 네이버클라우드 자원 전반에 적용된다. 서버·네트워크·CLOVA Studio가 모두 같은 크레딧에서 빠진다.
- 주최측의 별도 비용 보전은 없다.
- 잔여 크레딧은 `ncloud.com > 마이페이지 > 결제 관리 > 크레딧 및 할인 관리 > 콘솔`에서 확인한다.

## 5. CLOVA Studio 이용량 한도

| 모델 | 테스트 앱 | 서비스 앱 |
| --- | --- | --- |
| HCX-005 | 60 RPM / 60,000 TPM | 300 RPM / 180,000 TPM |
| HCX-007 | 60 RPM / 60,000 TPM | 180 RPM / 300,000 TPM |

- TPM은 실제 소비 토큰이 아니라 **`input token` + `maxTokens`**로 계산된다. `maxTokens`를 타이트하게 잡으면 429를 줄일 수 있다.
- 서비스 앱은 요건을 충족하면 즉시 승인된다. 참가팀별 한도 확대는 불가하다.
- 429로 답변에 실패해도 주최측이 구제하지 않는다. 타임아웃 안에 답변이 나와야 한다.

## 6. 기술 제약

- 형태소 분석기, 규칙 기반 NLP 라이브러리에 사용 제한은 없다.
- HyperCLOVA X 외 모델 사용 제한은 공지사항을 따른다. 전처리 단계 포함 여부, 임베딩·리랭커 해당 여부는 명시된 답이 없다.

## 7. 아직 답이 없는 것

| 질문 | 상태 |
| --- | --- |
| HTTPS 필수 여부, 경로·포트 지정 | 금주 중 공지 예정 |
| 평가 서버 가동 시간대 | 공지 예정 |
| 전처리 단계의 타 LLM 사용 가능 여부 | 「공지사항 참고」로 답변. 명시 없음 |
| 임베딩·리랭커가 LLM 제한에 포함되는지 | 답변 없음 |
| 근거 표기 형식이 채점 기준인지 | 답변 없음 |
| 서비스 앱 신청 시 「신청할 작업」 목록이 비어 있는 문제 | ncloud 고객지원으로 안내. 미해결 |
| PAT 관리자 승인 | 요청 접수. 대기 중 |

## 8. 지금 코드가 요구사항과 맞는지

| 요구사항 | 현재 | 판정 |
| --- | --- | --- |
| 응답 항목이 모두 string | `AnswerSuccessResponse` 5개 필드 전부 `String` | 맞음 |
| 타임아웃 300초 안에 응답 | `HCX_TIMEOUT_SECONDS` 기본 30초 | 맞음. 여유 있음 |
| 429 대응 | 429·타임아웃·5xx를 지수 백오프로 3회까지 재시도 | 맞음 |
| `maxTokens` | `HCX_MAX_TOKENS` 기본 1024 | 측정 후 조정 |

429는 `HcxErrorType.RATE_LIMIT` → `ServiceUnavailableException` → 503으로 나간다. 주최측이 5xx에
재시도 2회를 하지만 「429로 답변에 실패해도 구제하지 않는다」가 공지 내용이므로 우리 쪽에서 먼저 막는다.

`RetryingHcxClient`가 한 곳에서 재시도를 맡는다(Spring AI 안쪽 재시도는 꺼 둔다).

- 다시 거는 것: `RATE_LIMIT`(429) · `TIMEOUT` · `UPSTREAM`(5xx)
- 즉시 실패: `AUTHENTICATION` · `CONFIGURATION` · `INVALID_RESPONSE` — 다시 걸어도 같다
- 대기는 1초에서 2배씩, 한 번에 최대 8초. `Retry-After` 헤더가 있으면 그 값을 따른다
- 총 대기 예산 120초. 서버가 큰 `Retry-After`를 줘도 예산을 넘길 대기는 하지 않고 실패한다

최악의 경우에도 시도 3회 × 호출 타임아웃 30초 + 대기 예산 120초 = **210초**로 평가 타임아웃
300초 안이다. 기본 백오프만 쓰면 대기는 1초 + 2초뿐이다.

재시도를 다 써도 실패하면 503으로 나간다. 근거를 찾았는데 문장만 못 만든 것을 답변 불가로
내보내면 시스템 실패를 정상 답변으로 위장하는 것이라 그렇게 하지 않는다
(`docs/data-model.md` §9와 같은 이유).
