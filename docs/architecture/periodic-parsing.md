# 정기공시 요약재무정보 파싱 설계

- 문서 상태: Accepted
- 적용 범위: `preprocess/chaltteok_etl/periodic/`
- 관련 이슈: #24, #43, #49
- 최종 수정일: 2026-09-04

## 1. 목적

정기공시(사업·반기·분기보고서)에서 비교·계산에 쓸 재무 수치를 `PreprocessResult`로 뽑는 규칙을 정한다.
이 문서의 수치와 커버리지는 **정기공시 1,054건 전수 조사** 결과이며, 추정이 아니다.

## 2. 파싱 대상: `III. 재무에 관한 사항 > 1. 요약재무정보`

보고서 전체가 아니라 이 중단원 하나만 파싱한다.

| 근거 | 확인 결과 |
|---|---|
| 보편성 | 1,054건 중 **1,051건에 존재**. 나머지 3건은 XML이 아닌 `pdf+html` 대체 수집분 |
| 크기 | 섹션 중앙값 25,603자 = **원문의 0.76%** (사업보고서 1건은 약 6MB) |
| 연결·별도 | `가. 요약연결재무정보` / `나. 요약별도재무정보`가 함께 있어 `scope`를 실제로 채울 수 있다 |
| 기간 | 한 표에 **3개 기간**(제56/55/54기)이 있어 문서 1건으로 비교·계산을 검증할 수 있다 |

문서에 있는 값을 모두 뽑는 것이 목적이 아니라, 답해야 할 질문에 필요한 값을 뽑는 것이 목적이다.
다른 섹션은 새로운 질문 유형이 필요해질 때 추가한다.

## 3. 섹션 탐색 — 목차를 잡지 않는다

`1. 요약재무정보` 문자열은 **목차에도 등장**한다. 문자열 검색을 쓰면 목차를 먼저 잡는다
(표본 12건 중 3건에서 재현: 삼성중공업·이마트·POSCO홀딩스).

`<SECTION-2>` 바로 아래 `<TITLE>` 엘리먼트만 중단원 제목으로 인정한다.

```python
RE_SECTION2 = re.compile(r"<SECTION-2[^>]*>\s*<TITLE[^>]*>([^<]*)</TITLE>", re.S)
```

섹션의 끝은 다음 `<SECTION-2` 또는 `</SECTION-1` 중 먼저 오는 위치로 한다.

DART XML은 표준 XML 파서로 열리지 않는 문서가 있어 정규식 기반 텍스트 처리를 쓴다
(`docs/data-model.md` §2.5).

## 4. 기간 컬럼 — 연도가 아니라 기수(`제N기`)를 앵커로 쓴다

### 결정 근거

| 앵커 | 커버리지 |
|---|---|
| 기수 `제N기` | 982건 (93.4%) |
| 연도 토큰 `20XX` | 934건 (88.9%) |
| **둘 중 하나 이상** | **1,015건 (96.6%)** |
| 둘 다 없음 | 36건 (3.4%) |

연도 표기는 형식이 제각각이지만, 기수는 공백 변형 7종뿐이라 정규식 하나로 흡수된다.

```
['구 분', '제55기 1분기', '제54기', '제53기']                       ← 삼성전자: 연도가 없다
['구 분', '제24기(2023년 3월말)', '제23기 (2022년 12월말)', ...]    ← 현대오토에버
['구 분', '2023년 3분기 (제9기)', '2022년 (제8기)', ...]           ← 두산로보틱스: 순서가 반대
['구 분', '제 29기 1분기(2023. 3.31)', '제 28기 (2022.12.31)', ...] ← 카카오: 점 구분 날짜
['과 목', '제20(당)기 기말', '제 19(전)기 기말', '제 18(전전)기 기말']   ← 하나금융지주: 기수와 '기' 사이
['과 목', '제5(당)기말', '제4(전)기말', '제3(전전)기말']                ← 우리금융지주: 같은 형태
```

```python
# 제56기 / 제 56 기 / 제 56기 / 제56 기 / 제56(당)기 / 제 55(전)기 / 제5(전전)기말
RE_PERIOD_NO = re.compile(r"제\s*(\d+)\s*(?:[(（][^)）]{0,8}[)）])?\s*기")
```

#### ⚠️ 기수와 `기` 사이에 당기·전기 표시가 낀다

금융지주 두 곳은 `제20(당)기`처럼 기수 뒤에 당기·전기 표시를 괄호로 넣는다.
숫자 바로 뒤에 `기`를 요구하면 이 표기를 놓치고, 이 문서들은 **연도 표기도 없어서**
대체 앵커도 걸리지 않는다. 표를 하나도 인식하지 못해 문서 전체가 `PeriodicParseError`로
버려졌다 — 하나금융지주 18건 전부와 우리금융지주 9건이 여기에 걸려 있었다.

### 연도 역산 규칙

```
당기 컬럼   = 기수가 가장 큰 컬럼 (컬럼 순서가 오름차순인 문서가 있다)
컬럼 j 연도 = base_year - (당기 기수 - 컬럼 j 기수)
컬럼 j 종료월 = 당기면 base_month, 아니면 12 (결산월; 70개사 전부 12월)
```

검증 결과:

- "기수가 1 줄면 연도도 1 준다" → 322건 검증, **100% 성립**
- "당기 컬럼 연도 = manifest `base_year`" → 376건 검증, **100% 일치**

즉 XML에 연도가 없어도 manifest만 있으면 기간을 확정할 수 있다.
기수가 없고 연도만 있으면 연도를 직접 쓰고, 둘 다 없으면 그 표를 건너뛴다.

## 5. 단위 — 표 단위로 스코프를 관리한다

정규화 후 단위는 4종뿐이다.

| 단위 | 건수 | 배수 |
|---|---|---|
| 백만원 | 723 | ×10^6 |
| 원 | 419 | ×1 |
| 천원 | 86 | ×10^3 |
| 억원 | 17 | ×10^8 |

표기 변형(`(단위 : 백만원)` `(단위:백만원)` `(단위: 백만원)`)은 공백 무시 정규식으로 흡수한다.

### 행 단위가 표 단위를 덮어쓰지 않게 한다

한 표 안에 단위가 다른 행이 섞인다. 삼성전자 연결 요약표에는 마지막에
`기본주당순이익(단위 : 원)` 행이 있는데, 이를 표 단위로 오인하면 **매출액이 100만분의 1로 계산된다.**

- **표 단위**: 셀 전체가 단위 표기인 경우만 인정한다 (`(단위 : 백만원)` 한 칸짜리 행)
- **행 단위**: 항목명에 붙은 단위는 그 행에만 적용된다. 추출 대상 6종에 주당이익이 없으므로 무시한다
- 표 안에 단위 선언이 없으면 **표 앞에서 마지막으로 선언된** 단위를 쓴다 (첫 번째가 아니다)

## 6. `fact_key` 매핑 — 화이트리스트 정확일치

라벨 정규화는 네 가지를 처리한 뒤 공백을 없애고 비교한다.

| 처리 | 예 | 주의 |
|---|---|---|
| 선행 번호·ASCII 로마자 접두 제거 | `2.당기순이익` `I.영업수익` | |
| **전각 로마자 접두 제거** | `Ⅰ.영업이익` (신한지주) | `Ⅰ`은 U+2160이라 ASCII `I`와 다른 글자다 |
| 들여쓰기 기호 제거 | `ㆍ매출액` `·당기순이익` | |
| **라벨 전체를 감싼 대괄호 제거** | `[매출액]` → `매출액` | 아래 주의 |

### ⚠️ 대괄호는 라벨 전체를 감쌀 때만 벗긴다

이마트·삼성SDI·에코프로비엠·두산로보틱스·삼성생명은 `[매출액]`처럼 라벨 전체를 감싼다.
앞뒤 기호를 보이는 대로 지우면 `영업이익(손실)`의 닫는 괄호까지 지워져 **기존에 맞던 매칭이
깨진다.** 실제로 그렇게 짰다가 `operating_profit`이 64사에서 60사로 줄어드는 것을 확인했다.

`^\[(.+)\]$`로 전체를 감싼 경우만 벗기고, 벗긴 뒤 남은 접두를 한 번 더 지운다(`[Ⅰ.영업이익]`).
`[유동자산]`처럼 대상이 아닌 항목은 벗겨도 화이트리스트에 없으므로 그대로 걸러진다.

| fact_key | 인정 라벨 | 비고 |
|---|---|---|
| `total_assets` | `자산총계` | 70개사 전부 같은 낱말. 아모레퍼시픽·하이브는 `[자산총계]`로 감싼다 |
| `total_liabilities` | `부채총계` | 〃 |
| `total_equity` | `자본총계` | 〃 |
| `revenue` | `매출액` `영업수익` `매출` `영업수익(매출액)` | 매출액 49사 / 영업수익 8사 |
| `operating_profit` | `영업이익` `영업이익(손실)` `영업이익(영업손실)` `영업손실` `영업손익` | 21사가 `(손실)` 병기형 |
| `net_income` | `당기순이익` `당기순이익(손실)` `당기순이익(당기순손실)` `연결당기순이익` `연결총당기순이익` `총당기순이익` `당기연결순이익` `반기순이익` `분기순이익` `당기순손실` `연결당기순손실` `반기순손실` `분기순손실` | 손실 계열은 두산로보틱스가 쓴다. 아래 주의 |

### ⚠️ `net_income`에 부분일치를 쓰지 않는다

비금융 기준으로 "순이익"을 포함하는 라벨이 **201종**이다. 부분일치로 짜면 다음을 잘못 집어온다.

- `기본주당순이익` / `희석주당순이익` — **단위가 원**이라 금액을 100만분의 1로 만든다
- `비지배지분순이익` / `지배회사지분순이익` — 지분별 몫이지 총액이 아니다
- `법인세비용차감전순이익` — 세전이익이다
- `계속영업당기순이익` — 계속영업 부문만이다

같은 이유로 `매출총이익`은 `revenue`가 아니고, `부채와자본총계`·`부채및자본총계`는 `total_equity`가 아니다.

## 7. 기간 기준과 연결·별도

| 구분 | fact_key | `period_basis` | 날짜 필드 |
|---|---|---|---|
| 손익 | `revenue` `operating_profit` `net_income` | `cumulative` | `period_start`~`period_end` |
| 재무상태 | `total_assets` `total_liabilities` `total_equity` | `point_in_time` | `as_of_date` |

표 안의 위치가 아니라 `fact_key`로 판정한다. 위치 기반 판정은 문서마다 표 구조가 달라 깨진다.

### `scope` 판정 순서

원문이 기준을 밝히는 방식이 세 가지라 순서대로 확인한다.

1. **표 머리글의 괄호 표기** — `제44기 1분기말(연결)`.
   머리글은 그 표에만 적용되므로 섹션 소제목보다 구체적이다. 먼저 본다.
   한 머리글에 연결과 별도가 섞여 있으면 판정하지 않는다.
2. **섹션 소제목** — 표기가 여섯 가지다. 전부 인정한다.

   | 형태 | 예 | 쓰는 곳 |
   |---|---|---|
   | 요약 → 기준 → 재무정보 | `가. 요약연결재무정보` | 다수 |
   | 기준 → 요약 → 재무정보 | `1) 연결 요약재무정보` | 다수 |
   | `재무정보`가 아니라 `재무제표` | `가. 연결 요약재무제표` | 현대건설·엘에스일렉트릭 |
   | 기준을 괄호 안에 | `(1) 요약재무정보(연결재무제표 기준)` | 현대자동차 |
   | 기준을 괄호로 앞뒤에 | `가. (연결)요약재무정보` `요약재무정보 ( 연결 )` | 세아베스틸지주·한전기술 |
   | `요약`이 없다 | `가. 연결재무제표` | 현대제철·신한지주 |

3. **연결 소제목 바로 뒤의 기준 없는 소제목** — `가. 요약연결재무정보` / `나. 요약재무정보`.
   DART 사업보고서가 쓰는 짝이다. 뒤쪽에 `별도`라는 말이 없을 뿐 별도 표다.
4. 위 셋으로 확정되지 않으면 **추정하지 않고 `unknown`으로 기록한다**
   (`docs/data-model.md` §5).

#### 3번의 경계

앞에 연결 소제목이 **없으면** 그대로 `unknown`이다. 연결을 만들지 않는 회사의
`요약재무정보`까지 별도로 단정하지 않는다(한미반도체·시프트업·두산퓨얼셀).

바로 앞이 **별도**였으면 건드리지 않는다. 짝이 아니라 표가 셋 이상인 문서라 근거가 약하다
(한전기술·우리금융지주).

이 규칙으로 `unknown`이 **6,980건 → 719건**이 됐다. `consolidated` 17,836건은 하나도
바뀌지 않았다 — 연결로 잡혀 있던 것을 별도로 옮기지 않았다는 뜻이다.

| scope | 이전 | 이후 |
|---|---|---|
| `consolidated` | 17,836 | 17,836 |
| `separate` | 11,276 | **17,537** |
| `unknown` | 6,980 | **719** |

별도 기준 질문에 답하는 기업이 70개사 중 이만큼 늘었다.

| 항목 | 이전 | 이후 |
|---|---|---|
| 별도 매출액 | 41 | **62** |
| 별도 영업이익 | 44 | **67** |
| 별도 당기순이익 | 42 | **62** |
| 별도 자산총계 | 45 | **68** |

연결 기준 답변 건수는 그대로다(매출액 64 · 영업이익 68 · 당기순이익 63 · 자산총계 69).

#### `요약`이 없는 형태는 소제목 번호를 앵커로 요구한다

`연결재무제표`는 본문에도 흔히 나온다. `당사는 연결재무제표를 작성하고 있습니다`를
소제목으로 읽으면 뒤따르는 표가 통째로 잘못된 기준을 받는다. 그래서 이 형태만은
앞에 소제목 번호(`가.` `나)` `(1)` `1-1.`)를 요구한다.

소제목이 짧은 블록에 놓인다는 성질로 거르는 방법도 시도했으나, `separate`가
`consolidated`로 바뀌는 사실이 981건 생기고 파마리서치가 다시 전부 `unknown`이 되어
되돌렸다. 실제 문서의 소제목이 항상 짧은 `<P>` 블록에 있지는 않다.

#### ⚠️ 번호는 글 조각의 맨 앞에 있어야 한다

번호만으로는 본문과 갈리지 않는다. 본문 문장 속에 같은 모양이 들어 있다.

```
"가. 재무제표 재작성 등 유의사항"을 참고하시기 바랍니다   ← 다른 단원을 가리키는 안내문
(주2) 제20기(당기) 재무제표는 주주총회 승인전 재무제표     ← '(당기)'의 '기)'가 번호와 같은 모양
```

실제 소제목은 태그 바로 뒤에서 시작한다(`<SPAN …>가. 요약 연결 재무정보`).
그래서 번호 앞에 `(?:^|>)\s*`를 요구한다. 이 두 문장은 하나금융지주 요약재무정보
섹션의 연결 손익표보다 **앞에** 놓여 있어서, 걸러 내기 전에는 연결 손익 6건이
`unknown`으로 떨어졌다. 삼성생명도 같은 이유로 24건이 `unknown`이었다.

번호는 `1-1.`처럼 두 단계로 쓰는 문서가 있다(현대제철). 맨 앞 요구와 함께 넣지 않으면
`1-1. 연결재무제표`를 통째로 놓쳐 108건이 `unknown`이 된다.

### 기준을 밝히지 않은 소제목은 앞 기준을 물려받지 않는다

`가. 요약 연결 재무정보` 다음에 `나. 요약 재무정보`가 오는 문서가 있다(카카오 등).
두 번째 표는 별도인데 소제목에 기준을 적지 않는다.

기준을 밝힌 소제목만 위치로 모으면, 이 표가 앞 소제목의 기준을 물려받아 **별도 수치가
연결로 기록된다.** 카카오 2024년 영업수익은 연결 7,871,692백만원인데 별도
2,595,101백만원이 함께 연결로 남아, 질문에 3배 틀린 값이 나갈 수 있었다.

그래서 기준을 밝히지 않은 요약재무정보 소제목도 위치로 모은다. 그 자리를 남긴 뒤
연결 바로 뒤에 오는 것만 별도로 읽고, 그 밖에는 `unknown`으로 둔다.

### 판정 결과

적재된 36,092건 기준이다.

| | consolidated | separate | unknown | 전부 unknown인 기업 |
|---|---:|---:|---:|---:|
| 어순 2종만 볼 때 | 41.2% | 24.0% | **34.7%** | 11사 |
| 표기 6종으로 넓힌 뒤 | 49.4% | 31.6% | 19.1% | 0사 |
| **번호를 글 조각 맨 앞으로 좁힌 뒤** | **49.4%** | **31.2%** | **19.3%** | **0사** |

마지막 줄에서 `unknown` 비율이 조금 오르는 것은 판정이 나빠져서가 아니다.
하나금융지주 596건이 새로 들어왔고, 그중 별도 표 298건이 소제목에 기준을 적지 않았기
때문이다. 기존 69개사에서 판정이 나빠진 곳은 없다.

이 표는 「연결 뒤의 기준 없는 소제목을 별도로 읽는」 규칙을 넣기 전 수치다. 그 규칙을
넣은 뒤에는 `unknown`이 19.3% → **2.0%**(6,980건 → 719건)가 된다. §「`scope` 판정 순서」 참고.

전부 `unknown`이던 11개사는 어떤 재무 질문에도 답하지 못했다. 파서가 연결·별도를
밝히지 않은 질문도 연결기준으로 보기 때문에 `unknown` 사실과 만나지 않는다.
현대자동차 · 현대제철 · 현대건설 · 현대로템 · 한전기술 · 파마리서치 ·
세아베스틸지주 · 엘에스일렉트릭 · 우리기술 · 신한지주 · KB금융이었다.

**OCI홀딩스는 별도 243건이 연결로 붙어 있었는데 바로잡혔다.** 원문 표3(연결 손익계산서)
2,649,691,893천원, 표8(별도 손익계산서) 226,038,780천원과 일치한다. 무판정보다 나쁜
상태였다.

삼성생명 24건은 한때 `unknown`으로 물러났다가, 소제목 번호를 글 조각 맨 앞으로 좁히면서
전부 판정된다. 본문 안내문을 소제목으로 잡던 것이 원인이었다.

**하나금융지주 별도 표 298건은 한때 `unknown`이었다.** `가. 요약 연결 재무정보` 다음이
`나. 요약 재무정보`인데, 뒤 표는 자산총계 25.6조로 명백히 별도이면서도 소제목에 기준이 없다.

처음에는 "앞이 연결이었으니 뒤는 별도"라고 추론하는 것이 무판정 원칙을 바꾸는 설계 변경이라
보고 하지 않았다. 이후 이 짝(`가. 요약연결재무정보` / `나. 요약재무정보`)이 DART 사업보고서의
관례이고 카카오·대우건설·미래에셋증권·HMM 등 여러 기업이 같은 꼴을 쓴다는 것을 확인해
판정 규칙으로 넣었다. 추론의 근거가 "앞 소제목"이 아니라 "서식 관례"라 무판정 원칙과
어긋나지 않는다. 경계는 §「`scope` 판정 순서」의 「3번의 경계」에 적었다.

## 8. 네 가지 처리 상태 — 빈 결과를 정상으로 내보내지 않는다

`docs/data-model.md` §9에 따라 "값 없음"과 "파싱 실패"를 반드시 구분한다.
파싱 실패가 빈 결과로 저장되면, `/answer`가 **파서 버그를 정상적인 답변 불가로 위장**한다.

| 상태 | 처리 | 전수 결과 |
|---|---|---|
| **정상** | fact 생성 | 1,034건 (98.1%) |
| **단위 미확인** | `raw_value`는 보존하고 `normalized_value=None` | 7건 (0.7%) |
| **값 없음(정상)** | 문서·근거만 저장, fact 없음 | 7건 (0.7%) |
| **파싱 실패** | `PeriodicParseError` 발생 | 3건 (0.3%) |
| **대상 아님** | `UnsupportedDocument` 발생 | 3건 (0.3%) |

### 값 없음 (우리기술 7건)

공시가 값이 없다고 스스로 밝힌 경우다. 정상 결과로 처리한다.

> "당사는 소규모기업에 해당하여 별도로 기재하지 아니 하였습니다."
> "당사는 기업공시서식 작성기준에 따른 소규모기업에 해당하므로 '요약재무정보' 기재를 생략합니다."

표를 인식하지 못했는데 위와 같은 근거 문구도 없으면 **파싱 실패로 올린다.**

### 단위 미확인 (고려아연 6건 · 우리기술 1건)

고려아연 일부 보고서는 요약재무정보 섹션에 **단위 표기가 아예 없다.**
값의 자릿수로 보아 원 단위로 보이지만 추정하지 않는다.
값을 버리지도 않는다 — `raw_value`를 보존하고 `normalized_value`를 비워, **비어 있다는 사실 자체를 데이터에 남긴다.**

### 파싱 실패 3건

| 기업 | 건수 | 업종 |
|---|---|---|
| 우리기술 | 2 | 산업재 |
| 한국항공우주 | 1 | 산업재 |

요약재무정보 섹션에 표가 없고, 「소규모기업이라 미기재」 같은 근거 문구도 없는 문서다.

한때 하나금융지주 18건과 우리금융지주 9건이 여기에 있었다. 표 구조 문제로 적었으나
실제 원인은 **표 머리글의 기수 표기 하나**(`제20(당)기`)였다. §4 참조. 표 구조도 라벨도
그대로 읽힌다.

## 9. 답변 — 보고서 기준연도와 질문 연도는 다를 수 있다

한 보고서가 세 기간을 담으므로, **질문한 해가 기준연도인 보고서가 없어도 답할 수 있다.**
코퍼스 접수가 2023-01-01부터라 `base_year`는 2023년부터지만, 2023년 사업보고서에
2022·2021년 값이 함께 실려 있다.

```
2021년 손익 항목  1,173건 · 68개사
2022년            2,402건 · 70개사
```

`FinancialAnswerHandler`는 기준연도가 같은 보고서를 먼저 찾고, 없으면 **그 해 수치를 담은
보고서**를 찾는다. 질문 연도에 가까운 보고서를 먼저 본다. 뒤에 나온 보고서일수록 그 해 수치가
다시 작성됐을 수 있어, 그 해를 담은 보고서 중 가장 이른 것이 원래 공시된 값에 가깝다.

어느 보고서에서 나온 값인지 처리 요약에 남긴다.

```
삼성전자·2021년·매출액·연결기준 식별 → '사업보고서 (2023.12)'(2024-03-12) 검색
→ 매출액 279조 6,047억원(279,604,799백만원) 확인
```

분기·반기보고서에는 그 해 누적치가 섞여 있어, 기간이 한 해를 다 덮는지 확인한 뒤 쓴다(§7).
