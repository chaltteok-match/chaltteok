# 평가 API 요청·응답 명세

- 문서 상태: Draft v0.1
- 적용 범위: MVP 평가용 외부 API
- 기준 자료: 공식 과제 소개 자료의 평가용 API 서버 스키마 예시
- 최종 수정일: 2026-08-06

## 1. 목적

이 문서는 평가 클라이언트와 Chaltteok 서버가 `GET /answer`로 주고받는 외부 API 형식을 정의한다. Java DTO, Controller, 검증 로직과 API 테스트는 이 문서를 기준으로 구현한다.

이 문서에서 정의하는 외부 API 형식과 검색·계산 과정에서 사용하는 내부 모델은 분리한다. 내부에서는 근거 목록, 계산 정보와 처리 상태를 구조화해 관리할 수 있지만, 외부 응답은 이 문서에 정의된 JSON 형식으로 변환해 반환한다.

## 2. 공통 규칙

| 항목 | 값 |
| --- | --- |
| HTTP 메서드 | `GET` |
| 경로 | `/answer` |
| 요청 형식 | URL query parameter |
| 응답 형식 | JSON |
| 문자 인코딩 | UTF-8 |
| 성공 Content-Type | `application/json` |
| 인증 | MVP 평가 API에서는 사용하지 않음 |
| API 버전 경로 | 사용하지 않음 |

- JSON 필드명은 이 문서에 적힌 `snake_case`를 그대로 사용한다.
- 모든 정상 응답 필드는 필수이며 `null`을 반환하지 않는다.
- 명세에 없는 필드를 정상 응답에 추가하지 않는다.
- 제공된 공시 데이터만 답변 근거로 사용한다.
- 공시에서 확인할 수 없는 내용은 생성하거나 추측하지 않는다.
- 답변 불가는 정상적인 분석 결과로 처리하며 HTTP 200과 정상 응답 스키마를 사용한다.
- 잘못된 요청이나 시스템 장애만 오류 응답으로 처리한다.

## 3. 요청 명세

### 3.1 Query parameters

| 이름 | 위치 | 타입 | 필수 | 검증 규칙 | 설명 |
| --- | --- | --- | --- | --- | --- |
| `question_id` | query | string | 필수 | 누락 불가, 공백 제거 후 빈 문자열 불가 | 평가 질문 식별자 |
| `question` | query | string | 필수 | 누락 불가, 공백 제거 후 빈 문자열 불가 | 평가 질의 원문 |

세부 규칙:

- `question_id`는 서버에서 새로 생성하거나 변경하지 않고 응답에 그대로 반환한다.
- `question_id`는 의미를 해석하지 않는 식별 문자열이며 대소문자를 구분한다.
- `question`은 URL decoding 후의 원문을 응답에 그대로 반환한다.
- 공백 여부를 검증할 때만 앞뒤 공백을 제거한 값을 사용하며, 반환할 원문 자체는 수정하지 않는다.
- 한글과 특수문자는 UTF-8 기준으로 URL encoding해서 전송한다.
- 두 파라미터 중 하나라도 누락되거나 공백뿐이면 HTTP 400을 반환한다.

### 3.2 cURL 요청 예시

```bash
curl -G "https://{team-endpoint}/answer" \
  --data-urlencode "question_id=Q-001" \
  --data-urlencode "question=OO기업의 2025년 연결기준 매출액은 얼마인가?"
```

## 4. 정상 응답 명세

### 4.1 상태 코드

```text
200 OK
```

### 4.2 응답 필드

| JSON 필드 | JSON 타입 | Java 타입 | 필수 | `null` 허용 | 설명 |
| --- | --- | --- | --- | --- | --- |
| `question_id` | string | `String` | 필수 | 불가 | 요청으로 받은 평가 질문 식별자 |
| `question` | string | `String` | 필수 | 불가 | 요청으로 받은 평가 질의 원문 |
| `retrieved_context` | string | `String` | 필수 | 불가 | 답변 생성에 실제로 사용한 공시 근거 |
| `think_trace` | string | `String` | 필수 | 불가 | 검색·추출·계산·판단 과정의 검증 가능한 요약 |
| `answer` | string | `String` | 필수 | 불가 | 사용자에게 반환하는 최종 답변 |

Java 필드명은 `camelCase`를 사용할 수 있지만, 직렬화된 JSON 필드명은 반드시 위 표의 `snake_case`와 일치해야 한다.

### 4.3 `retrieved_context` 작성 규칙

`retrieved_context`에는 최종 답변을 도출할 때 실제로 사용한 근거만 포함한다. 검색했지만 답변에 사용하지 않은 문서는 포함하지 않는다.

근거 한 건은 다음 정보를 포함한다.

- 공시명
- 공시일: `YYYY-MM-DD`
- 기업명
- 답변에 사용한 문장, 표의 항목 또는 수치

여러 공시를 사용한 경우 하나의 문자열 안에서 `[근거 1]`, `[근거 2]` 순서로 구분한다.

```text
[근거 1]
공시명: 2025년 사업보고서
공시일: 2026-03-20
기업명: OO기업
근거: 연결 포괄손익계산서의 매출액은 12,345억원이다.

[근거 2]
공시명: 주요사항보고서
공시일: 2025-08-10
기업명: OO기업
근거: 시설투자 금액은 1,000억원이다.
```

근거를 찾지 못한 경우 `null` 대신 빈 문자열 `""`을 반환한다.

### 4.4 `think_trace` 작성 규칙

`think_trace`는 모델의 비공개 내부 사고과정이나 프롬프트 원문이 아니라, 답변을 검증하는 데 필요한 처리 단계의 요약이다.

포함할 수 있는 내용:

- 질문에서 식별한 기업, 기간과 공시 유형
- 검색하고 선택한 공시
- 사용한 수치와 단위
- 비교·계산식
- 정정·후속공시 적용 여부
- 답변 불가로 판단한 이유

포함하지 않는 내용:

- 시스템 프롬프트 또는 전체 프롬프트 원문
- API 키, 환경변수와 내부 서버 정보
- Java stack trace나 데이터베이스 오류 원문
- 모델의 비공개 내부 사고과정

예시:

```text
기업·기간·연결기준 식별 → 2025년 사업보고서 검색 → 연결 매출액과 단위 확인 → 근거와 답변 수치 일치 검증
```

계산이 포함된 경우 사용한 값을 명시한다.

```text
2024년 매출액 10,000억원과 2025년 매출액 12,000억원 확인 → 증감률=(12,000-10,000)/10,000×100=20% 계산
```

### 4.5 `answer` 작성 규칙

- 질문이 요구한 결론을 먼저 제시한다.
- 사용한 수치에는 단위를 함께 표시한다.
- 비교·계산 질문에는 비교 기준과 계산 결과를 명시한다.
- 이력 질문에는 최초 공시와 최신 정정·변경·해지 상태를 구분한다.
- 근거 공시명과 공시일을 표시한다.
- 근거가 부족하면 추측하지 않고 정보 한계를 명시한다.
- 미래 예측이나 투자 의견을 생성하지 않는다.

## 5. 정상 응답 예시

아래 값은 스키마 설명을 위한 예시이며 실제 공시 답변이 아니다.

```json
{
  "question_id": "Q-001",
  "question": "OO기업의 2025년 연결기준 매출액은 얼마인가?",
  "retrieved_context": "[근거 1]\n공시명: 2025년 사업보고서\n공시일: 2026-03-20\n기업명: OO기업\n근거: 연결 포괄손익계산서의 매출액은 12,345억원이다.",
  "think_trace": "기업·기간·연결기준 식별 → 2025년 사업보고서 검색 → 연결 매출액과 단위 확인 → 근거와 답변 수치 일치 검증",
  "answer": "OO기업의 2025년 연결기준 매출액은 12,345억원입니다. 근거는 2026-03-20 공시된 2025년 사업보고서입니다."
}
```

## 6. 답변 불가 응답

### 6.1 처리 원칙

다음은 서버 오류가 아니라 정상적인 답변 불가 결과다.

- 제공된 공시 데이터에서 관련 근거를 찾지 못한 경우
- 근거는 찾았지만 질문의 결론을 뒷받침하기에 부족한 경우
- 제공 데이터의 대상 기업 또는 기간을 벗어난 경우
- 미래 예측이나 투자 의견을 요구하는 경우
- 제공 코퍼스 외부 정보가 필요한 경우

앞의 다섯 중 **미래 예측·투자 의견**과 **기간 밖 질문**은 Handler에 넘기기 전에 가려낸다
(`QuestionScope`). 기업명과 항목이 들어 있으면 Handler가 나서서 근거를 찾기 때문에,
앞날을 묻는 질문에 과거 수치가 답으로 나갈 수 있다.

기간은 접수일이 아니라 **값의 연도**로 본다. 정기공시 요약재무정보 표가 한 번에 세 기간을
담아 2020년치 값까지 들어 있다. 접수 기간(2023-01-01~)으로 자르면 답할 수 있는 질문을 막는다.

대상 기업 밖은 따로 가리지 않는다. `CorpNameResolver`가 코퍼스 기업을 찾지 못하면 어느
Handler도 나서지 않아 이미 답변 불가로 간다. 다만 **코퍼스 기업 이름을 앞에 단 다른 법인**은
가려낸다. `카카오뱅크`를 `카카오`로 읽으면 다른 회사의 수치가 답으로 나간다.

이 경우 HTTP 200과 정상 응답 스키마를 유지한다.

- `question_id`: 요청값을 그대로 반환
- `question`: 요청 원문을 그대로 반환
- `retrieved_context`: 근거가 전혀 없으면 `""`, 부분 근거가 있으면 해당 근거만 기록
- `think_trace`: 답변 불가 사유를 간략히 기록
- `answer`: `제공된 공시 데이터에서는 확인할 수 없습니다.` 또는 `공시에서 확인되지 않습니다.`를 명시

### 6.2 답변 불가 예시

```json
{
  "question_id": "Q-002",
  "question": "OO기업의 2027년 매출액을 예측해줘.",
  "retrieved_context": "",
  "think_trace": "제공 데이터의 대상 기간을 벗어난 미래 예측 질문으로 판단",
  "answer": "제공된 공시 데이터에서는 확인할 수 없습니다. 공시에 근거하지 않은 미래 예측은 제공하지 않습니다."
}
```

## 7. 오류 응답

### 7.1 오류와 답변 불가의 구분

| 상황 | HTTP 상태 | 응답 형식 |
| --- | --- | --- |
| 답변 생성 성공 | 200 | 정상 응답 |
| 근거 부족·범위 밖·미래 예측 | 200 | 답변 불가 응답 |
| 필수 파라미터 누락 또는 공백 | 400 | 오류 응답 |
| 허용하지 않은 HTTP 메서드 | 405 | 오류 응답 |
| 서버 내부의 예상하지 못한 오류 | 500 | 오류 응답 |
| HyperCLOVA X, DB 등 필수 의존 서비스의 일시 장애 | 503 | 오류 응답 |

### 7.2 오류 응답 필드

| JSON 필드 | JSON 타입 | Java 타입 | 필수 | `null` 허용 | 설명 |
| --- | --- | --- | --- | --- | --- |
| `question_id` | string 또는 null | `String` | 필수 | 허용 | 요청에서 식별자를 정상적으로 받았다면 해당 값, 아니면 `null` |
| `error_code` | string | `String` | 필수 | 불가 | 클라이언트가 분기 처리할 고정 오류 코드 |
| `message` | string | `String` | 필수 | 불가 | 사람이 이해할 수 있는 오류 설명 |
| `retryable` | boolean | `boolean` | 필수 | 불가 | 같은 요청을 나중에 재시도할 수 있는지 여부 |

### 7.3 오류 코드

| HTTP 상태 | `error_code` | `retryable` | 발생 조건 |
| --- | --- | --- | --- |
| 400 | `INVALID_REQUEST` | `false` | `question_id` 또는 `question` 누락·공백 |
| 405 | `METHOD_NOT_ALLOWED` | `false` | `/answer`에 GET 이외의 메서드 사용 |
| 500 | `INTERNAL_SERVER_ERROR` | `false` | 분류되지 않은 서버 내부 오류 |
| 503 | `SERVICE_UNAVAILABLE` | `true` | HyperCLOVA X 또는 DB 등의 일시 장애 |

오류 메시지에는 API 키, 내부 경로, stack trace와 외부 서비스의 원문 오류를 포함하지 않는다.

### 7.4 잘못된 요청 예시

```json
{
  "question_id": "Q-003",
  "error_code": "INVALID_REQUEST",
  "message": "question은 필수이며 공백일 수 없습니다.",
  "retryable": false
}
```

`question_id` 자체가 누락되거나 공백인 경우 다음처럼 반환한다.

```json
{
  "question_id": null,
  "error_code": "INVALID_REQUEST",
  "message": "question_id는 필수이며 공백일 수 없습니다.",
  "retryable": false
}
```

## 8. 구현 경계

### 8.1 외부 DTO

외부 정상 응답 DTO는 다음 다섯 필드만 제공한다.

```text
question_id
question
retrieved_context
think_trace
answer
```

현재 임시 API의 `answer`, `evidences`, `status` 응답은 최종 계약이 아니며 이 명세를 구현할 때 교체한다.

### 8.2 내부 모델

내부 `AnswerResult`는 다음과 같이 외부 DTO보다 많은 정보를 가질 수 있다.

- 구조화된 근거 목록
- 사용한 수치와 단위
- 계산식과 중간 계산값
- 정정·후속공시 관계
- 답변 가능 여부와 정보 한계

Controller는 `AnswerService`가 반환한 내부 `AnswerResult`를 외부 응답 DTO로 변환한다. 검색·계산·이력 판단·LLM 호출 로직은 Controller와 DTO에 작성하지 않는다.

### 8.3 초기 구현 범위

Java DTO와 기본 `/answer` 적용 단계에서는 실제 검색과 HyperCLOVA X가 연결되지 않아도 된다. 다만 다음은 동작해야 한다.

- 두 요청 파라미터 검증
- 정상 응답의 다섯 필드 반환
- JSON 필드명의 `snake_case` 직렬화
- 답변 불가와 오류 응답 형식 반환
- 정상·답변 불가·잘못된 요청에 대한 Controller 테스트

실제 공시 검색·계산·이력 추적과 HyperCLOVA X 응답은 이후 각 공시 흐름에서 연결한다.

## 9. 명세 검토 기준

- [ ] 요청 파라미터의 이름, 타입, 필수 여부와 검증 규칙이 구현 가능하다.
- [ ] 정상 응답 다섯 필드가 공식 평가 스키마와 일치한다.
- [ ] JSON 필드명과 Java 필드명의 변환 방법이 명확하다.
- [ ] 답변 불가와 시스템 오류가 구분되어 있다.
- [ ] 여러 공시 근거와 계산 과정을 문자열 필드에 일관되게 표현할 수 있다.
- [ ] 현재 임시 `/answer`를 이 명세로 교체할 범위가 명확하다.
- [ ] 이후 정기공시·거래소공시·주요사항보고서·지분공시 흐름이 같은 응답 형식을 사용할 수 있다.
